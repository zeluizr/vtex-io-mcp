# Security

This guide provides an overview of the robust security measures implemented by VTEX, including authentication, access control, logging, attack protection, and incident response.

## Certifications

VTEX regularly audits its information security controls through independent professionals. At the application layer:

- **ISO 27001** – Information Security Management System
- **SOC 1 – Type 2**: Reports covering internal controls over financial reporting systems
- **SOC 2 – Type 2**: Reports covering security, availability, integrity, confidentiality, and privacy
- **PCI** – Validation of controls around cardholder data to reduce credit card fraud

At the data storage layer, AWS has several certifications for its data centers, including ISO 27001, FedRAMP authorization, PCI certification, and SOC reporting.

## Authentication

To access information within a VTEX account, authentication is required along with the necessary permissions. Authentication is required for:

- Logging in to the VTEX Admin or to the store website
- Developing apps or integrations

By default, VTEX adopts logical segregation for each account's data, isolating it from other accounts.

### Two-factor authentication

Two-factor authentication (2FA) is mandatory for users to access the VTEX Admin with email and password. Two options are available:

- Using a key generated by an authentication app
- Using a key sent by SMS

This requirement only applies to email and password logins, not to other login methods such as Google, Facebook, or access code.

### Password rules

VTEX Admin and store passwords must have at least:

- 8 characters
- 1 number
- 1 uppercase letter
- 1 lowercase letter

Merchants can enforce password expiration after 15, 30, or 90 days.

### Login integrations

Native login integrations are available for Facebook (webstore) and Google (webstore and VTEX Admin).

Single sign-on (SSO) is supported with integration options for external identity providers on both the Admin and store website:

- **Admin**: Uses the SAML 2.0 authentication protocol
- **Store website**: Uses the OAuth 2.0 protocol

## Authorization and access control

VTEX manages logical access with the principle of least privilege and segregation of duties. Users are granted access only to what is strictly necessary for their roles.

### Roles and permissions

**License Manager** is the system that ensures the security of operations by verifying that a user or API key has the necessary permissions.

- **Resource**: An entity associated with an action or information within VTEX infrastructure (e.g., "View order" resource)
- **Role**: Determines the set of resources a group of users can access. Each user can be associated with one or more roles

Roles can be:
- **Predefined roles**: Provided by VTEX out of the box
- **Custom roles**: Created by selecting specific resources

## Logs

All operations on the platform are automatically logged. Platform errors are logged in SIEM (Security Information and Event Management) software.

VTEX actively monitors application and infrastructure logs for patterns indicative of potential security risks.

For merchant access, the **Audit** tool in the VTEX Admin allows searching and investigating store history using filters.

## Attack protection

VTEX uses advanced antivirus, firewalls, and content filters to block malware. Protection includes:

- DDoS (Distributed Denial of Service) attack protection
- Regular backups of critical data
- Constant monitoring of activities for suspicious behavior

### Web Application Firewall (WAF)

Available through VTEX Shield as an additional layer of protection. Helps filter and block malicious traffic before it reaches the store.

### Secure Sockets Layer (SSL)

VTEX generates and automatically renews an SSL certificate for your store. The certificate is issued via Let's Encrypt and VTEX is responsible for its creation at go-live.

## Penetration tests and vulnerability reports

The Security team regularly performs vulnerability checks, including recurring scans and penetration tests. Merchants may request the **Attestation of Penetration Testing** report upon request to Support.

> The VTEX Master Services Agreement (MSA) expressly forbids performing penetration tests against the VTEX platform without prior written consent.

## Security incident response

VTEX has a formal protocol for security incident response covering: preparation, incident identification, containment, eradication, recovery, and post-incident.

### Disaster recovery plan

VTEX has a disaster recovery plan tested at least once a year. It covers:

- Detailed guidelines for unplanned incidents (natural disasters, cyber attacks, disruptive events)
- Defined standard RPO (Recovery Point Objective) and RTO (Recovery Time Objective) objectives
- Backup tests for plan effectiveness

### Business continuity plan

A business continuity plan addresses challenges arising from emergencies, ensuring a smooth transition and minimizing impacts.

## VTEX Shield

VTEX Shield is an add-on product that offers supplementary, customizable protection layers for stores that prioritize platform resilience. Requires contacting Commercial Support. Additional fees may apply.
