# Authentication

Authentication is a crucial aspect of API integrations, backend, and frontend app development. It ensures authorized access by requiring valid credentials like API keys or tokens.

## Authentication methods overview

| Use case | Recommended method |
|----------|-------------------|
| Backend VTEX IO app | User token via VTEX IO context, or app authentication token via VTEX IO context if needed |
| Frontend VTEX IO app | User token via VTEX IO context |
| Self-hosted backend request to VTEX APIs | Application keys (appKey + appToken) |
| Self-hosted frontend request to VTEX APIs | User token |

## Authentication methods

### Application keys (API keys)

An `appKey` + `appToken` pair used for server-side integrations. Each key must be associated with roles that grant the necessary permissions.

- Used for: self-hosted backend integrations, CI/CD pipelines, ERP integrations, scripts
- Headers: `X-VTEX-API-AppKey` and `X-VTEX-API-AppToken`
- Guide: [API authentication using application keys](https://developers.vtex.com/docs/guides/api-authentication-using-api-keys)

### User tokens

Tokens generated from a user session. Used for frontend and backend VTEX IO apps via the IO context.

- Used for: VTEX IO apps (frontend and backend), self-hosted frontend requests
- Guide: [API authentication using user tokens](https://developers.vtex.com/docs/guides/api-authentication-using-user-tokens)

### App authentication tokens

Tokens generated by the VTEX IO platform for apps running within the IO infrastructure. Provides the app's own identity when calling APIs.

- Used for: backend VTEX IO apps that need to act as the app itself (not on behalf of a user)
- Guide: [App authentication using auth tokens](https://developers.vtex.com/docs/guides/app-authentication-using-auth-tokens)

## Single sign-on (SSO) integrations

VTEX allows stores to integrate with external identity providers for SSO experiences for both shoppers and Admin users.

| Integration | Protocol | Guide |
|-------------|----------|-------|
| Store SSO | OAuth 2.0 | [Store SSO with OAuth 2.0](https://developers.vtex.com/docs/guides/login-integration-guide-webstore-oauth2) |
| Admin SSO | SAML 2.0 | [Admin SSO with SAML 2.0](https://developers.vtex.com/docs/guides/login-integration-guide-admin-saml2) |
| VTEX as OAuth provider | OAuth 2.0 | [Use your VTEX account as an OAuth provider](https://developers.vtex.com/docs/apps/vtex.oauth-provider-admin@2.x) |

General SSO guide: [Login (SSO)](https://developers.vtex.com/vtex-rest-api/docs/login-integration-guide)

## Authorization

Authentication (proving who you are) is separate from authorization (what you're allowed to do). VTEX uses **License Manager** for authorization:

- **Users**: Individual accounts with access to the VTEX Admin or APIs
- **Roles**: Sets of resources (permissions) assigned to users
- **License Manager Resources**: Granular permissions for each VTEX module action

See: [Users](https://help.vtex.com/en/subcategory/users--63DHe3VQEEE6Uuua8gIs2M), [Roles](https://help.vtex.com/en/tutorial/roles--7HKK5Uau2H6wxE1rH5oRbc), [License Manager Resources](https://help.vtex.com/en/tutorial/license-manager-resources--3q6ztrC8YynQf6rdc6euk3)

## Auditability

All authenticated operations are logged. Use the **Audit** tool in the VTEX Admin to search and investigate store history.

See: [Audit](https://help.vtex.com/en/tutorial/searching-for-events-on-audit--5RXf9WJ5YLFBcS8q8KcxTA)
