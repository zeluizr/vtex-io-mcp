# Google Pay

Integration guide for Google Pay in VTEX payment connectors.

---

## Overview

Google Pay provides digitized card tokens for payment processing. Two token types are used:

| Type | Full name | Description |
|---|---|---|
| **DPAN** | Device Primary Account Number | Token specific to the device/wallet; no CVV |
| **FPAN** | Funding Primary Account Number | Actual card number from the issuing bank |

---

## Payment Fields for Google Pay

When Google Pay is used, the connector receives additional fields in the `POST /payments` request:

| Field | Type | Description |
|---|---|---|
| `cryptogram` | string | 3D Secure cryptogram from Google Pay token |
| `eci` | string | Electronic Commerce Indicator — authentication result |
| `paymentOrigin` | string | `"GooglePay"` — identifies the payment source |

---

## DPAN vs FPAN — CVV Handling

| Token Type | CVV Required | Description |
|---|---|---|
| **DPAN** | ❌ No CVV | Device token — CVV not available and not required |
| **FPAN** | ✅ CVV present | Real card number — CVV may be included |

> For DPAN transactions, do not require or validate CVV. The `cscToken` field will be absent or empty.

---

## cryptogram Field

The `cryptogram` is a one-time-use value generated by Google Pay that cryptographically proves the payment was authorized by the cardholder. Pass it to the acquirer for authorization.

---

## eci Field

The ECI (Electronic Commerce Indicator) communicates the result of authentication:

| ECI Value | Meaning |
|---|---|
| `05` / `02` | Fully authenticated (3DS successful) |
| `06` / `01` | Authentication attempted |
| `07` / `00` | No authentication |

Pass the ECI to the acquirer — it affects liability shift.

---

## paymentOrigin

Always `"GooglePay"` for Google Pay transactions. Useful for:
- Analytics and reporting
- Applying different routing rules for wallet payments
- Debugging

---

## /manifest Declaration

Google Pay is typically associated with existing card payment methods. No separate entry in `/manifest` is needed — it's handled at the acquirer level.
